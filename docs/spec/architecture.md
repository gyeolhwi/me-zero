# 설계 개요 - 프로필 레이어·수집 루프·대변 에이전트

> 상태: 설계안. 아직 구현된 코드는 없다.

## 목표

"MBTI 4글자"가 아니라 **근거가 붙은 나에 대한 주장들의 모음**을 계속 쌓고 고친다.
그 모음을 프롬프트로 컴파일해, 내가 할 법한 판단·말투로 응답하는 에이전트를 만든다.

## 1. 프로필 레이어

| 레이어 | 담는 것 | 예 |
|---|---|---|
| identity | 역할·경력·현재 상황 | 웹 개발자, 주로 다루는 스택 |
| traits | 성향 지표 | MBTI, Big Five 점수와 해석 |
| style | 말투·글쓰기·의사결정 방식 | 짧게 결론부터, 표 선호 |
| values | 가치관·우선순위·싫어하는 것 | 속도보다 정확성 |
| preferences | 도구·취향 | 에디터, 음식, 게임 |
| episodes | 주장의 근거가 되는 실제 사례 | 특정 상황에서 내린 선택 |

## 2. 주장(claim) 단위

모든 항목을 하나의 형식으로 저장한다. 그래야 "수립·수정·확보"를 기계적으로 할 수 있다.

```yaml
- id: style-answer-first
  layer: style
  claim: 결론을 먼저 말하고 근거는 짧게 붙인다
  confidence: 0.7        # 0~1, 근거가 쌓이면 올라가고 반례가 나오면 내려간다
  evidence: [episodes/2026-11-18-chat.md]
  source: interview      # interview | artifact | feedback | self-report
  status: active         # active | disputed | retired
  updated: 2026-11-18
```

- 저장은 Markdown + YAML 로 하고 git 으로 관리한다. 커밋 이력이 곧 "내 성향이 어떻게 바뀌었는지"의 기록이 된다.
- 지운 주장은 삭제하지 않고 `retired` 로 둔다.

## 3. 수집 루프

1. **인터뷰**: 에이전트가 신뢰도가 낮거나 비어 있는 레이어부터 질문한다. 정해진 검사(MBTI·Big Five 문항) + 상황형 질문("이럴 때 너라면?").
2. **산출물 분석**: 내가 쓴 글·커밋 메시지·대화 기록에서 말투·습관 후보를 뽑아 `confidence` 낮게 제안한다. 확정은 내가 한다.
3. **교정 피드백**: 에이전트 답변에 "이건 나 아님 / 맞음"을 표시하면 해당 주장의 신뢰도가 바뀌고 새 episode 가 생긴다.

## 4. 대변 에이전트

- `active` 주장 중 신뢰도가 기준 이상인 것만 골라 레이어별로 시스템 프롬프트를 만든다(compile).
- 모르는 영역은 지어내지 않고 "아직 모름"이라고 답하고, 그 질문을 인터뷰 대기열에 넣는다.

## 5. 얼마나 나와 닮았는지 재기

- 내가 직접 답한 질문 세트를 따로 둔다(eval set).
- 에이전트 답과 내 답을 비교해 일치율을 기록한다. 프로필을 바꿀 때마다 다시 잰다.

## 6. 공개 범위

- 저장소는 public 이다. 원본 대화·일기·연락처 같은 원본 데이터는 `private/` (gitignore) 에만 둔다.
- 커밋되는 프로필은 공개해도 되는 요약만 담는다.

## 제안 단계

1. 주장 스키마와 레이어 폴더를 만들고, 손으로 10~20개 채운다.
2. 인터뷰 루프 (Claude Code 스킬 또는 CLI) 로 빈 레이어를 채운다.
3. compile 스크립트로 시스템 프롬프트를 만들고 대변 에이전트를 돌린다.
4. eval set 과 교정 피드백을 붙인다.
